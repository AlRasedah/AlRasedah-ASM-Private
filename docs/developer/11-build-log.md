# 11. Build log: how the app was made

This is the history of the initial build (September 2026), written so the next developer
knows the order things were built in, what went wrong along the way, how it was fixed, and
what has and has not been verified.

## 11.1 Starting point

- Empty repository; requirements: an independent ASM platform (not a fork), scanners as
  replaceable sensors, Docker Compose deployment, multi-tenant from day one, Saudi-hostable,
  delivered milestone by milestone with tests.
- Build machine: Windows 11, Python 3.13, Node 24, Docker CLI present.
- **Docker was not usable**: Docker Desktop did not start from the build session, and the
  Docker daemon inside WSL Ubuntu required root, which was deliberately not escalated. A
  PostgreSQL was still needed for RLS tests, so a **user-space PostgreSQL 18** was
  assembled inside WSL from `apt-get download` packages (missing `libnuma1`/`liburing2`
  fetched the same way) and started on port 55432. This became
  `scripts/dev-postgres-wsl.sh`.
- Consequence: container images were written but **never built or run** during the build.

## 11.2 Order of construction

1. **Architecture first** (on paper): sensors as a separate package, coverage-based change
   detection, RLS tenancy, sync SQLAlchemy, Celery state machine, VARCHAR enums.
2. **Sensor framework** (`workers/asm_sensors`) — observation schema, target validation,
   safe subprocess runner, adapter base, registry, jobs/sealing, runner, Celery worker, then
   all ten adapters, then recorded fixtures and 43 tests. Built first because it has no
   dependencies and fixes the contract everything else consumes.
3. **Backend core** — config, crypto, security, logging, rate limiting, errors, request
   context, DB base/session with the RLS listener.
4. **Models** for every milestone at once (the schema was a first deliverable), one
   autogenerated migration `0001` extended by hand with `pg_trgm`, `apply_rls()` and the
   audit trigger; tested upgrade → downgrade → upgrade.
5. **Domain services** in dependency order: audit → permissions → auth → profiles/tenants →
   normalization/cloud → scope checker → change detector → settings → findings service →
   **ingestion engine** → scope service → risk → detection rules → storage/secrets →
   targets → orchestrator → metrics.
6. **Tests of the core pipeline** before any HTTP: pure unit tests (40), RLS isolation (7),
   change-detection scenarios (10), full inline pipeline with replayed tool output (5).
7. **REST API** — deps, schemas, routers; notification engine, intel, reporting, workers,
   maintenance; API tests (16).
8. **Lint pass** (ruff) and CLI.
9. **Deployment** — Dockerfiles, entrypoints, nginx, PostgreSQL init, compose file
   (validated with `docker compose config`), env generators.
10. **Web UI** — design system, client/auth, all pages; type-check, build, smoke tests (21);
    route-level code splitting.
11. **Demo data** (`seed_demo.py`) and a local run of API + UI.
12. **Documentation** — README, product docs, licensing inventory, CI, then this handbook.

## 11.3 Problems met and how they were solved

| Problem | Cause | Fix |
|---|---|---|
| Migration downgrade failed on `DROP TABLE tenant_memberships` | the `users` RLS policy references `tenant_memberships` | drop the policy first in `downgrade()` |
| Test scope entries for `alpha.example` rejected | `.example` is not a public suffix; `normalize_entry` refuses non-registrable domains (correct behaviour) | tests use `alpha-corp.com` |
| `alembic.ini` unreadable | PowerShell `Set-Content -Encoding utf8` wrote a BOM | file rewritten without BOM (edit config files with an editor, not PowerShell pipes) |
| Built-in profiles vanished between tests | `TRUNCATE tenants CASCADE` also truncates `scan_profiles` (FK) | re-seed built-ins in `db_clean` |
| IP-enrichment stage always "No authorized targets" | derived IPs need `derived_from` for authorization; the IP stage didn't pass it | `build_targets` supplies the resolution map for `IP_ENRICHMENT` |
| Nuclei SSL result mapped to a port, test expected hostname | when the IP is known, `ip:port` is the more specific asset | kept behaviour, fixed the test |
| Host disappearance test counted two events | the host's derived IP also left the surface (legitimate INFO event) | test asserts the hostname event specifically |
| Dev UI port 5173 occupied | unrelated process | Vite reads `PORT`; launch config uses auto port |
| Recharts 2 flagged unmaintained | upstream EOL | upgraded to Recharts 3 (same component API used) |
| Two filter changes in one click lost one | consecutive `setSearchParams` calls in React Router 6 | `useFilters().setMany` |
| `redis:7-alpine` licensing | Redis ≥ 7.4 is RSALv2/SSPL | switched to Valkey 8 |
| Demo login rejected ("special-use or reserved name") | strict email validation refused `demo.local` | permissive `Email` type (ADR-018) + regression test |
| Global scan concurrency limit ineffective | counted in a tenant session, so RLS hid other tenants' scans | count in a system session + regression test (found while writing this handbook) |
| Report doc risk examples | first draft computed by hand | recomputed with the real engine; table now matches code |
| Wazuh rule regex | OS_Regex has no character classes | `type="pcre2"` on the risk-score field |

## 11.5 Rebrand to the Al-Rasedah design system (18 September 2026)

The web UI was moved from its original teal/slate theme to the Al-Rasedah Technology brand
(ADR-019, chapter 7.8).

1. **Extraction.** The existing UI vocabulary — `styles.css` variables and classes, the
   `ui.tsx`/`Layout.tsx`/`Charts.tsx`/`Timeline.tsx` components — was inventoried (22
   components) and recorded as a design system together with the brand's palette, fonts,
   logo and voice from alrasedah.com.sa. The result is the "Al-Rasedah" design-system
   artifact (brand book, tokens with contrast-checked usage notes for both themes, component
   guidelines and previews), available from the product owner.
2. **Application to the code:**
   - `frontend/src/styles.css` rewritten: `@font-face`, navy/copper tokens (dark default,
     light theme), all component classes kept by name.
   - `frontend/src/fonts/` added (Inter variable, IBM Plex Sans Arabic ×4; SIL OFL 1.1,
     listed in `THIRD_PARTY_LICENSES.md`).
   - `public/brand-symbol.svg` added; `favicon.svg` replaced; `BrandMark` renders the logo
     instead of the inline teal radar.
   - Hex colours removed from TSX: `Charts.tsx` (grid, tooltip, default bar),
     `Dashboard.tsx` (series and severity bars → `var(--brand)`, `SEV_COLOR`),
     `ScanDetail.tsx`, `Integrations.tsx`, `FindingDetail.tsx` (old `--ok/--warn/--accent/
     --muted/--font` references renamed).
   - Report default accent `#1f6f78` → `#a3571f` in `backend/app/reporting/service.py` and
     `charts.py`; Settings placeholder updated.

| Old variable | New token |
|---|---|
| `--bg`, `--bg-2` | `--background`, `--background-subtle` |
| `--panel`, `--panel-2`, `--panel-3` | `--surface`, `--surface-elevated`, `--surface-muted` |
| `--text`, `--text-2`, `--muted` | `--foreground`, `--foreground-muted`, `--foreground-subtle` |

| `--radius-sm` on controls | `--radius-control` (6px → 8px) |

**Verified:** `npm run typecheck`, `npm test` (21/21), `npm run build` (fonts and logo in
`dist/`), backend report test, login page viewed in the dev server, every design-system
component preview rendered in both themes. **Not verified:** authenticated screens viewed
after the rebrand, the light theme inside the running app (no toggle yet), the `asm-web`
image rebuilt with the change, a PDF report rendered with the new accent.

## 11.6 Fixes from the software test report and clickability audit (18 September 2026)

Two manual test passes against a running stack (IFMI demo scope) reported the issues below.
Each was reproduced or explained from the code before changing anything; regressions are
in `tests/backend/test_review_fixes.py` (13) and the last block of
`frontend/src/test/pages.test.tsx` (4).

| Report item | Finding | Change |
|---|---|---|
| Audit log shows #44, 43, **41** yet "Chain intact" | Not tampering: `#` was the table-wide `id`, shared with the platform chain and other tenants and consumed by rollbacks. The hash chain itself was intact. But verification only checked hash links, and the UI invited this reading. | Gapless per-chain `chain_seq` (migration `0002`), shown as `#`; `check_chain` also fails on sequence gaps and reports a reason; badge shows the entry count and the failure reason. |
| Audit CHANGE column truncated | — | Row click opens the full entry (before/after JSON, user agent, request id). |
| Tenant **Suspend** fires immediately and can lock out the admin | No confirmation; the backend allowed suspending the tenant the caller was signed in to. Also found: **scheduled scans kept running** for suspended tenants. | Confirm dialog; Suspend disabled for the current tenant and rejected by the API (422); `due_schedules` skips suspended tenants; after a correct password, sign-in says the organization is suspended (`403 tenant_suspended`) instead of a generic error. |
| API-key delete has no confirmation | Also unconfirmed: alert-policy delete, schedule delete, user remove, API-token revoke. | `Confirm` on all five, plus Deactivate. |
| Users page has no edit path | The role select, Deactivate and Remove existed but are hidden on your own row (the tester's only row). Admin MFA reset was genuinely missing. | "You · manage in Account" on your own row; `POST /users/{id}/mfa/reset` (not for yourself; a tenant admin cannot reset platform admins or accounts shared with other tenants). |
| Add user shows the raw email regex | The validation handler returned pydantic's raw `msg`. | Plain-language messages with the field name (`Email: Enter a valid email address`); patterns never echoed. |
| Finding Activity shows an assignee UUID | Assignment activity stores the user id. | API adds `summary` ("Assigned to Sara Analyst"). |
| Sortable-looking headers that don't sort | Inventory IP/Status/Owner/Tags and Findings Asset/Status/Detection. Also found: **severity sort was alphabetical** (text column). | Status/Owner and Asset/Status/Detection now sort; severity sorts by rank; sortable headers are buttons with a ↕/↑/↓ indicator and `aria-sort`, and IP and Tags have no control. |
| Clearing the Findings search leaves stale results | Not reproduced in jsdom. Clearing now applies immediately instead of after the 350 ms debounce, and the native `search` event is handled too. | Regression test asserts the next request has no `q`. |
| Deep Assessment amass stage "stalled" for 40 min | Expected: that profile gives amass 90 min + 5 min grace, and amass reports nothing until it finishes. | Running stages show "running for 40m of up to 1h 35m" (`time_limit_seconds` on stages) and warn once past the limit. |
| Bold timeline titles look like links; dashboard/scan stat cards not clickable | — | Only linked titles are emphasised, and an asset's own events don't link to itself. All dashboard KPI cards link to the matching filtered view; scan KPI cards open the Changes tab. Finding titles are real links. |
| **Status/Approval dropdowns discard mouse selections** (High) | **Not changed.** Both are ordinary controlled `<select>`s with no reset path (`refetchOnWindowFocus` is off). The clickability audit reports the same Change-status dropdown working. Automation tools that click native `<option>` elements are a known cause of exactly this pattern (mouse fails, keyboard and programmatic work). | Needs a manual re-test with a real mouse before any change. |

## 11.7 Product renamed to Exteriq ASM (18 September 2026)

The product formerly called *AlRasedah ASM* is **Exteriq ASM**. Al-Rasedah Technology
remains the company: copyright, licence identifiers, the security contact, the Al-Rasedah
visual identity (chapter 7.8) and the copper-eye logo are unchanged.

Renamed everywhere the product name appears — UI, page title, API title, e-mail subjects
and sender, report default brand, CLI, packages (`exteriq-asm`, `exteriq-asm-web`), Docker
comments and docs. Machine identifiers changed too; update anything outside the product that
matches on them:

| Identifier | Old | New | Who is affected |
|---|---|---|---|
| Notification `source` field, syslog tag/hostname, file-channel default name | `alrasedah-asm`, `alrasedah-asm.json` | `exteriq-asm`, `exteriq-asm.json` | Wazuh decoders/rules — re-install them from `docs/integrations/wazuh.md` (decoder and group now `exteriq-asm` / `exteriq_asm`); existing file channels keep their configured file name |
| Scanner identification header / User-Agent | `X-ASM-Scanner: AlRasedah-ASM`, `AlRasedah-ASM` | `Exteriq-ASM` | Customer WAF/IDS allowlists matching the header |
| DNS ownership TXT record | `_alrasedah-asm.<domain>` = `alrasedah-asm-verification=…` | `_exteriq-asm.<domain>` = `exteriq-asm-verification=…` | Nobody: records published under the old name **still verify** (`LEGACY_VERIFY` in `scope/service.py`) |

Environment variables (`ASM_*`), database and role names, Docker service and image names
(`asm-*`) and the image registry namespace are unchanged, so existing deployments and data
upgrade in place. A tenant's own report brand name (Settings → Report branding) is kept if set.

## 11.8 Recommended next steps

1. Run CI (or `docker compose build`) and fix anything the first real image build reveals.

   scans against a domain you own; compare observations with the fixtures and adjust

   `wazuh-logtest`.
